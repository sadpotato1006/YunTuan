# 云团挂件近距离互动 v0.7

## 行为

- 所有烧录 `0.8.0` 固件的云团挂件都持续发送互动广播并进行被动扫描。
- 只有本机和对方都开启社交模式时，RSSI 才会进入距离判断。
- 两米初始进入阈值为 `-65 dBm`，离开阈值为 `-72 dBm`。
- RSSI 使用 `75%` 历史值加 `25%` 新值的指数平滑；连续 3 个样本达到进入阈值才触发。
- 同一设备触发后冷却 60 秒；持续停留在范围内不会重复提醒。
- 提醒默认使用 500ms 短振动和提示音，并按小程序通过 `SET_ALERT_SETTINGS (0x09)` 下发的社交提醒、振动、声音开关执行。关闭提醒不影响相遇记录；录音、语音上传、TTS 或其他提醒占用期间最多延迟 3 秒，避免影响语音链路。
- 每次有效相遇还会产生 Control Event `0x24`。固件先把事件写入带 CRC 的双槽 NVS 环形队列，再通知小程序；离线、断电或重启后仍保留最近 20 次。
- 小程序先把事件保存到本地，再发送 `ACK_SOCIAL_ENCOUNTER (0x08)`；固件收到 ACK 后才删除队首记录。ACK 或 Notify 丢失时固件按 1.5～30 秒退避重发，小程序按 `encounterId` 去重。

## 广播格式

互动信息位于 BLE Manufacturer Data，固定 8 字节：

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0 | 2 | 开发期标识 `59 54`（YT） |
| 2 | 1 | 互动广播版本，当前为 `01` |
| 3 | 1 | flags，bit0 表示社交模式已开启 |
| 4 | 4 | 小端序开机随机匿名 ID |

广播不包含设备序列号、用户 OpenID 或微信信息。匿名 ID 每次开机重新生成。

## 小程序相遇事件与 ACK

Control 协议直接升级为 `1.7`。`SOCIAL_ENCOUNTER (0x24)` 的事件 payload 固定 18 字节：

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0 | 8 | `encounterId`：本次启动随机 ID + 事件序号，原始字节作为 16 位十六进制字符串保存 |
| 8 | 4 | 对方开机随机匿名 Token，小端序 |
| 12 | 1 | 触发时的平滑 RSSI，`int8` |
| 13 | 4 | 相遇 UnixTime，`uint32` 小端序；设备尚未校时时为 0 |
| 17 | 1 | flags；bit0 表示 UnixTime 有效 |

`ACK_SOCIAL_ENCOUNTER (0x08)` 请求 payload 固定为事件中的 8 字节 `encounterId`，成功响应附加 1 字节剩余队列数量。未知或重复 ACK 按幂等成功处理，但只有 ACK 与当前队首 ID 一致时才删除记录。

小程序收到事件后必须先同步写入 `yuntuan_social_encounters_v2`，成功后才能 ACK。名片查询在 ACK 之后异步进行；查询失败时保留匿名 Token 供重试，成功后立即从本地记录删除 Token，只保留允许公开的名片快照。页面不展示 `encounterId` 或匿名 Token。

连接初始化时小程序使用 `SET_TIME (0x05)` 给没有 RTC 的挂件校时。校时前产生的持久化事件使用接收时间并标记为估算时间。

为了让 8 字节互动信息进入 31 字节 legacy 主广播包，主广播只保留云团 Control Service UUID；Battery Service 仍可在连接后正常发现。设备连接手机后切换为不可连接广播，断开手机后恢复可连接广播，互动广播与扫描始终保持。

## 两米校准

`-65/-72 dBm` 是开发初值，不是物理距离的绝对换算。装入最终外壳后，将两台设备按实际佩戴方向放到两米，观察串口中的 `SOCIAL_PROXIMITY ... filteredRSSI=...`。如果两米处难以触发，将 `SOCIAL_ENTER_RSSI_DBM` 调小（例如 `-68`）；如果超过两米仍频繁触发，将其调大（例如 `-62`）。离开阈值建议始终比进入阈值低 7～10dB。
