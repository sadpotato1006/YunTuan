# 云团智能挂件软硬件 BLE 通信协议（联调评审稿）v0.2

> 文档状态：供小程序、硬件、产品团队评审，尚未冻结，不可直接作为量产规范。  
> 编写日期：2026-07-14  
> 适用对象：云团第一代智能挂件固件、微信小程序。  
> 本版目标：优先打通真实硬件最小闭环，量产安全绑定、音频和 OTA 在后续版本单独冻结。

## 1. 本次评审需要达成的结论

硬件与小程序团队应优先确认以下事项：

| 编号 | 待确认项 | 本稿建议 |
| --- | --- | --- |
| R01 | 无线方式 | BLE 4.2 或以上，挂件作为 Peripheral / GATT Server |
| R02 | 芯片与 SDK | 硬件部填写具体型号、SDK 和协议栈版本 |
| R03 | 默认 ATT MTU | 第一阶段按 23 字节设计，即单包应用数据最多 20 字节 |
| R04 | 自定义 UUID | 使用第 5 节给出的 128-bit UUID |
| R05 | 必做能力 | 广播、连接、电量、社交模式、设备按键、状态事件 |
| R06 | 输出器件 | 至少确认振动马达、蜂鸣器、指示灯是否存在 |
| R07 | 输入器件 | 至少确认单击、双击、长按能否可靠识别 |
| R08 | 实验室安全模式 | 第一阶段允许 `SecurityMode=0`，写指令暂不认证 |
| R09 | 量产认证能力 | 确认芯片是否支持真随机数、HMAC-SHA256、安全存储 |
| R10 | 断线重连 | 固件恢复广播，小程序有限次数重连 |
| R11 | 音频和 AI | 本协议不承载，需另行确认硬件是否独立联网 |
| R12 | OTA | 第一阶段不实现，只保留能力位 |

任何一项未确认时，应在会议纪要中写明负责人和确认日期。

## 2. 范围

### 2.1 第一阶段必须实现

- 小程序发现指定挂件；
- 建立和主动断开 BLE 连接；
- 发现标准服务和云团自定义服务；
- 读取协议版本和设备能力；
- 读取并订阅真实电量；
- 获取设备综合状态；
- 开启或关闭社交模式；
- 小程序触发振动或提示音查找设备；
- 挂件主动上报按键、低电量和状态变化；
- 处理超时、重复命令、蓝牙关闭和意外断线。

### 2.2 第一阶段不实现

- 实时音频传输、语音识别和 AI 对话；
- GPS、地图和蜂窝网络通信；
- OTA 固件升级；
- 老人和子女账号关系；
- 云端远程控制；
- 量产级设备所有权认证。

上述能力不得私自复用未分配的命令字，应在后续协议版本中增加。

## 3. 系统角色和边界

| 角色 | BLE 角色 | 职责 |
| --- | --- | --- |
| 云团挂件 | Peripheral / GATT Server | 广播、保存状态、执行命令、发送通知 |
| 微信小程序 | Central / GATT Client | 扫描、连接、写命令、订阅通知、展示状态 |
| 云函数 | 不参与 BLE | 后续用于设备归属、认证令牌和状态历史 |

BLE 通信只发生在手机和附近挂件之间。云函数不能直接连接用户身边的 BLE 设备。

## 4. 设备标识和广播

### 4.1 设备序列号

设备序列号 `deviceSn` 使用 16 个大写 ASCII 字符：

```text
YT + 产品代码2位 + 生产年份2位 + 流水号10位
```

示例：

```text
YT01260000000001
```

要求：

- 全生命周期唯一；
- 烧录后不可通过普通业务指令修改；
- `deviceSn` 是业务永久标识；
- 微信返回的 `deviceId` 只用于当前手机上的 BLE 连接，不能作为永久设备编号。

### 4.2 广播名称

```text
YT- + deviceSn 最后6位
```

示例：

```text
YT-000001
```

设备名称只用于筛选和展示，不作为认证凭据。

### 4.3 广播内容

设备处于未连接状态时，应发送可连接广播，至少包含：

- Flags；
- Complete Local Name 或 Shortened Local Name；
- Yuntuan Control Service UUID；
- 可选的标准 Battery Service UUID。

禁止广播完整 `deviceSn`、用户信息、设备密钥和绑定码。

### 4.4 建议广播参数

| 状态 | 广播间隔 | 持续时间 |
| --- | --- | --- |
| 实验室联调 | 100～250 ms | 持续广播 |
| 用户主动进入绑定模式 | 100～250 ms | 60 秒 |
| 已绑定等待重连 | 500～1000 ms | 由功耗测试决定 |
| 低电量 | 1000～2000 ms | 由功耗测试决定 |

建立连接后停止可连接广播；连接意外断开后，设备应在 1 秒内恢复广播。

## 5. GATT 服务和特征值

### 5.1 Device Information Service

| 项目 | UUID | 属性 | 第一阶段 |
| --- | --- | --- | --- |
| Device Information Service | `0x180A` | Service | 必须 |
| Model Number String | `0x2A24` | Read | 必须，例如 `YT-P01` |
| Firmware Revision String | `0x2A26` | Read | 必须，例如 `0.2.0` |
| Hardware Revision String | `0x2A27` | Read | 必须，例如 `A1` |
| Serial Number String | `0x2A25` | Read | 实验室可用，量产需评审权限 |

### 5.2 Battery Service

| 项目 | UUID | 属性 | 第一阶段 |
| --- | --- | --- | --- |
| Battery Service | `0x180F` | Service | 必须 |
| Battery Level | `0x2A19` | Read + Notify | 必须 |

Battery Level 为 1 字节无符号整数，合法范围 `0～100`。以下场景发送 Notify：

- 订阅成功后立即上报一次；
- 电量相对上次上报变化至少 1%；
- 电量跨越 20%、10%、5% 阈值；
- 充电状态导致电量变化。

### 5.3 Yuntuan Control Service

| 项目 | UUID | 属性 | 方向 |
| --- | --- | --- | --- |
| Yuntuan Control Service | `A92B1000-6E3B-4C5D-9F21-4A7C2D8E1B30` | Service | — |
| Command RX | `A92B1001-6E3B-4C5D-9F21-4A7C2D8E1B30` | Write 必须；Write Without Response 可选 | 小程序 → 挂件 |
| Event TX | `A92B1002-6E3B-4C5D-9F21-4A7C2D8E1B30` | Notify 必须；Indicate 可选 | 挂件 → 小程序 |
| Protocol Info | `A92B1003-6E3B-4C5D-9F21-4A7C2D8E1B30` | Read | 挂件 → 小程序 |

所有命令响应和主动事件都通过 Event TX 返回。小程序必须先订阅 Event TX，之后才能发送业务命令。

### 5.4 Protocol Info

Protocol Info 固定为 6 字节：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | ProtocolMajor | 当前为 `1` |
| 1 | 1 | ProtocolMinor | 当前为 `0` |
| 2 | 2 | Capabilities | uint16，小端 |
| 4 | 1 | SecurityMode | `0` 实验室；`1` 量产认证 |
| 5 | 1 | Reserved | 固定为 `0` |

Capabilities：

| Bit | 功能 |
| --- | --- |
| 0 | Battery Service |
| 1 | 社交模式 |
| 2 | 查找设备：振动或鸣响 |
| 3 | 设备按键事件 |
| 4 | 充电状态 |
| 5 | 设备时间同步 |
| 6 | 量产会话认证 |
| 7 | OTA，第一阶段不得置 1 |
| 8～15 | 保留，必须置 0 |

示例：设备支持电量、社交模式、查找、按键和充电状态，实验室模式下返回：

```text
01 00 1F 00 00 00
```

## 6. 基础编码规则

- 多字节整数统一使用小端序；
- 字符串统一使用 UTF-8，不带结尾 `\0`；
- 布尔值：`0x00=false`，`0x01=true`，其他值非法；
- 时间使用 uint32 Unix 秒；
- 所有保留位和保留字节发送时必须为 0；
- 接收方必须校验长度、范围和 CRC 后再执行命令。

## 7. 数据帧

### 7.1 帧结构

每次 Command RX 写入或 Event TX 通知使用以下格式：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | SOF | 固定 `0xA5` |
| 1 | 1 | Version | 固定 `0x01` |
| 2 | 1 | Flags | 帧类型 |
| 3 | 1 | Command | 命令字 |
| 4 | 1 | Sequence | 请求序号 |
| 5 | 1 | FragmentIndex | 第一阶段固定 `0` |
| 6 | 1 | FragmentCount | 第一阶段固定 `1` |
| 7 | 1 | PayloadLength | Payload 字节数，第一阶段 `0～10` |
| 8 | N | Payload | 命令负载 |
| 8+N | 2 | CRC16 | 低字节在前 |

第一阶段完整帧不得超过 20 字节，不实现分片。若后续命令需要超过 10 字节 Payload，双方评审分片规则后再启用，不能私自发送超长帧。

### 7.2 Flags

| Bit | 含义 |
| --- | --- |
| 0 | `1` 表示 Response |
| 1 | `1` 表示设备主动 Event |
| 2 | 保留，固定 0 |
| 3 | `1` 表示当前连接已完成量产认证 |
| 4～7 | 保留，固定 0 |

合法组合：

- 请求：`0x00`；
- 响应：`0x01`；
- 主动事件：`0x02`；
- 量产认证后的请求/响应在上述值基础上加 `0x08`。

### 7.3 Sequence

- 小程序请求使用 `1～255`；
- 递增到 255 后回到 1；
- 设备响应必须使用请求的相同 Sequence；
- 设备主动事件固定使用 Sequence `0`；
- 同一时间最多允许一个未完成请求。

### 7.4 CRC

使用 CRC-16/CCITT-FALSE：

| 参数 | 值 |
| --- | --- |
| Polynomial | `0x1021` |
| Init | `0xFFFF` |
| RefIn / RefOut | false / false |
| XorOut | `0x0000` |

计算范围从 Version 到 Payload 最后一个字节，不包含 SOF 和 CRC。CRC 在线路中低字节在前。

## 8. 通用响应

所有 Response 的 Payload 前 2 字节固定为 `StatusCode`，uint16 小端。只有 `StatusCode=0` 时，后面才允许携带命令响应数据。

| 状态码 | 名称 | 含义 |
| --- | --- | --- |
| `0x0000` | OK | 成功 |
| `0x0001` | UNKNOWN_COMMAND | 未知命令 |
| `0x0002` | INVALID_PAYLOAD | 长度或取值错误 |
| `0x0003` | BUSY | 设备忙 |
| `0x0004` | UNAUTHORIZED | 当前连接未认证 |
| `0x0005` | NOT_SUPPORTED | 硬件或固件不支持 |
| `0x0006` | INTERNAL_ERROR | 设备内部错误 |
| `0x0007` | CRC_ERROR | CRC 校验失败 |
| `0x0008` | VERSION_INCOMPATIBLE | 协议版本不兼容 |
| `0x0009` | LOW_BATTERY | 电量过低，拒绝操作 |
| `0x000A` | PHYSICAL_CONFIRM_REQUIRED | 需要实体按键确认 |

如果 SOF、帧长度或 CRC 无法可靠解析，固件可以丢弃该帧；如果已经能够识别 Command 和 Sequence，应返回对应错误响应。

## 9. 第一阶段命令

### 9.1 命令总表

| Command | 名称 | 请求 Payload | 成功响应附加数据 | 第一阶段 |
| --- | --- | --- | --- | --- |
| `0x01` | HELLO | 无 | 协议主版本、次版本、能力、安全模式、绑定状态 | 必须 |
| `0x02` | GET_STATUS | 无 | 电量、充电状态、社交模式、运行时间 | 必须 |
| `0x03` | SET_SOCIAL_MODE | enabled | 实际 SocialMode | 必须 |
| `0x04` | FIND_DEVICE | AlertType、Duration | 无 | 有振动或蜂鸣器时必须 |
| `0x05` | SET_TIME | UnixTime | 无 | 建议 |
| `0x06` | PING | Random | 原样返回 Random | 必须 |
| `0x10～0x1F` | 绑定和认证 | 后续定义 | 后续定义 | 预留 |

### 9.2 HELLO `0x01`

请求 Payload：无。

成功响应附加数据，即 StatusCode 后的数据：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | ProtocolMajor |
| 1 | 1 | ProtocolMinor |
| 2 | 2 | Capabilities，uint16 小端 |
| 4 | 1 | SecurityMode：0 实验室，1 量产 |
| 5 | 1 | BindState：0 未绑定，1 已绑定，2 绑定模式中 |

### 9.3 GET_STATUS `0x02`

请求 Payload：无。

成功响应附加数据：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | Battery | 0～100；无法获取时 `0xFF` |
| 1 | 1 | ChargingState | 0 未充电；1 充电中；2 已充满；255 未知 |
| 2 | 1 | SocialMode | 0 关闭；1 开启 |
| 3 | 4 | Uptime | uint32 秒，小端 |

### 9.4 SET_SOCIAL_MODE `0x03`

请求 Payload：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | Enabled：0 关闭；1 开启 |

成功响应附加数据：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | 实际 SocialMode |

固件必须先持久化或完成实际状态变更，再返回成功。小程序以响应值为准更新页面。

### 9.5 FIND_DEVICE `0x04`

请求 Payload：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | AlertType | 0 振动；1 提示音；2 振动+提示音 |
| 1 | 2 | Duration | uint16 毫秒，小端，范围 500～10000 |

成功响应无附加数据。重复 Sequence 不得导致设备重复振动或重复鸣响。

### 9.6 SET_TIME `0x05`

请求 Payload 为 4 字节 UnixTime，uint32 小端。成功响应无附加数据。

设备没有实时时钟时可以返回 `NOT_SUPPORTED`，但必须在 Capabilities 中关闭对应能力位。

### 9.7 PING `0x06`

请求 Payload 为 4 字节随机值，成功响应原样返回相同 4 字节。PING 不改变设备状态，用于联调和检测链路可用性。

## 10. 设备主动事件

事件 Flags=`0x02`，Sequence=`0`，不需要小程序返回应用层响应。

| Command | 名称 | Payload |
| --- | --- | --- |
| `0x20` | STATUS_CHANGED | Battery、ChargingState、SocialMode，共 3 字节 |
| `0x21` | BUTTON_EVENT | ButtonType 1 字节 + UnixTime 4 字节 |
| `0x22` | LOW_BATTERY | Battery 1 字节 |
| `0x23` | BIND_WINDOW_CHANGED | BindState 1 字节，第一阶段可不实现 |

ButtonType：

| 值 | 含义 |
| --- | --- |
| 1 | 单击 |
| 2 | 双击 |
| 3 | 长按 |

按键消抖、双击时间窗、长按时长由硬件部提出建议并在联调后冻结。事件中的 UnixTime 在设备时间未知时允许为 0。

## 11. 抓包示例

### 11.1 GET_STATUS 请求

Sequence=`0x01`，无 Payload：

```text
A5 01 00 02 01 00 01 00 A9 48
```

其中 CRC 计算输入为：

```text
01 00 02 01 00 01 00
```

CRC 结果为 `0x48A9`，线路顺序为 `A9 48`。

### 11.2 开启社交模式

小程序请求，Sequence=`0x02`：

```text
A5 01 00 03 02 00 01 01 01 AE E8
```

设备成功响应：

```text
A5 01 01 03 02 00 01 03 00 00 01 65 EC
```

响应 Payload `00 00 01` 表示 StatusCode=`OK`，实际 SocialMode=`1`。

## 12. 连接和初始化流程

```text
小程序打开蓝牙适配器
  → 扫描包含 Yuntuan Control Service UUID 的设备
  → 用户选择目标设备
  → 停止扫描
  → 建立 BLE 连接
  → 发现 GATT 服务和特征值
  → 订阅 Event TX
  → 订阅 Battery Level
  → 读取 Protocol Info
  → 校验主版本和能力位
  → 发送 HELLO
  → 发送 GET_STATUS
  → 进入 READY
```

任一步失败时，小程序都必须显示明确错误，关闭当前连接并允许重新尝试。

建议状态机：

```text
IDLE
  → SCANNING
  → CONNECTING
  → DISCOVERING
  → SUBSCRIBING
  → INITIALIZING
  → READY
  → RECONNECTING / ERROR
```

## 13. 超时、重试和幂等

| 操作 | 超时 | 重试策略 |
| --- | --- | --- |
| 扫描目标设备 | 10 秒 | 用户主动重试 |
| 建立 BLE 连接 | 8 秒 | 自动重试 1 次 |
| 服务发现和订阅 | 每步 5 秒 | 失败后断开重连 1 次 |
| 普通命令响应 | 2 秒 | 最多重试 2 次 |
| FIND_DEVICE | 3 秒 | 最多重试 1 次 |
| 意外断线 | — | 1 秒、3 秒、5 秒退避重连 |

重试规则：

- 同一次业务请求的重试必须复用原 Sequence；
- 设备缓存最近 16 个 Sequence 的响应至少 30 秒；
- 收到重复 Sequence 时返回缓存响应，不重复执行副作用；
- 小程序超时后不得同时发出下一条业务命令；
- 三次重连失败后停止自动重连，提示用户手动操作。

## 14. 状态一致性

- BLE 写接口返回成功只表示数据进入协议栈，不表示硬件已执行；
- 页面状态只能由相同 Sequence 的成功响应或设备主动事件更新；
- 每次重新连接、小程序从后台恢复、手机蓝牙重新开启后，重新执行 GET_STATUS；
- 正常连接期间依靠 Notify 更新，不高频轮询；
- 社交模式应保存到非易失存储，设备重启后保持上一次成功设置；
- 设备不支持的功能必须关闭 Capability 位并返回 NOT_SUPPORTED。

## 15. 实验室模式和量产模式

### 15.1 第一阶段实验室模式

- Protocol Info 中 `SecurityMode=0`；
- 仅用于指定测试硬件；
- HELLO、GET_STATUS、SET_SOCIAL_MODE、FIND_DEVICE、SET_TIME、PING 暂不要求认证；
- 固件版本号和日志必须能识别实验室固件；
- 实验室模式固件不得用于交付和量产。

### 15.2 量产前必须补充

- 每台设备独立密钥；
- 机身二维码和绑定码；
- 设备所有权绑定；
- 每次连接的会话认证；
- 写命令权限控制；
- 安全解绑和恢复出厂设置；
- 设备密钥安全存储、固件读保护和签名能力；
- 认证失败限速和审计。

量产认证继续使用 `0x10～0x1F` 命令范围，需硬件确认芯片能力后单独冻结。禁止以设备名称、MAC、`deviceId` 或固定默认密码代替认证。

## 16. 联调日志要求

双方日志至少包含：

- 时间；
- 连接状态；
- `deviceId` 的脱敏值；
- Service 和 Characteristic UUID；
- TX/RX 方向；
- Command、Sequence、StatusCode；
- 完整 HEX 帧；
- CRC、长度和超时错误。

量产日志不得记录设备密钥、绑定码、完整认证令牌和用户信息。

## 19. 版本兼容

- ProtocolMajor 不同：停止业务通信并提示版本不兼容；
- ProtocolMajor 相同且设备 Minor 更高：只使用当前小程序已知命令和字段；
- 不认识的命令返回 UNKNOWN_COMMAND；
- 已冻结字段不得改变含义；
- 新功能优先分配新命令字或新版本，不复用保留字节；
- 所有协议变更必须同时更新协议文档、固件版本和小程序测试用例。
